# HTTP 请求与响应：一次通信的基本结构

理解请求方法、状态码和消息体，有助于定位前后端联调中的问题。一条请求是否成功，需要结合响应状态与具体内容判断。

> 示例笔记，可以替换成自己的学习记录。

## 请求由什么组成

以一个简化的 HTTP/1.1 请求为例：

```http
GET /notes/ HTTP/1.1
Host: example.com
Accept: text/html
```

请求行表达要做什么，请求头补充上下文。有些请求还包含消息体。

## 先看状态码

| 状态码 | 常见含义 |
| --- | --- |
| 200 | 请求成功 |
| 301 | 资源永久移动 |
| 404 | 未找到资源 |
| 500 | 服务器内部错误 |

## 调试时的顺序

1. 确认请求地址和方法。
2. 查看响应状态及响应头。
3. 检查响应体是否符合预期。
4. 如果涉及缓存，确认看到的是否为最新内容。
